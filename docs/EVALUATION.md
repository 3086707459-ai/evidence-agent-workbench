# 评测范围与验收

## 已完成的工程验证

`evidence-agent evaluate` 在临时数据库中运行完整流程，输出 JSON，可由 CI 归档。`provider=demo` 明确标记 `live_model_tested=false`、`semantic_quality_scored=false`。

| 检查 | 通过标准 |
| --- | --- |
| 引用及多来源 | 精确原文引用，至少 2 个 document ID |
| 审批阻断 | 审批前无工单，投递器不能执行 |
| 摘要绑定 | 修改 action digest 被拒绝 |
| 受限计算 | 虚构样例三年费用 1920/1860；0.1+0.2=0.3 |
| 本地 outbox 幂等 | 重复审批与投递只产生一个本地工单 |
| 确定性回放 | 原快照报告一致、无模型 token、无新副作用 |
| 事件链 | 全部事件的链接与哈希有效 |
| 资料不足 | 显式 insufficient_evidence，claims 为空 |

单元/集成测试进一步覆盖实际子进程 SIGKILL、过期 lease fencing、在途取消、正常关闭、并发幂等、请求体限制、分离凭据、SSE 游标和官方 SDK 序列化。SDK 使用 httpx MockTransport，不发真实网络请求。覆盖率以实际运行报告为准，不设置“所有行为都已证明”的结论。

## 真实模型验收协议（待执行）

真实验收建议固定代码提交、模型 ID、语料摘要、提示词版本、参数和任务集版本，至少重复每个任务 3 次，并记录各次结果，不能只保留最好一次。

| 任务组 | 例子 | 标注与度量 |
| --- | --- | --- |
| 资料可回答 | 多文档选型、约束汇总、费用比较 | 原文定位、事实正确、结论完整、计算准确 |
| 资料缺失 | 未提供认证、未来市场份额 | 应弃答的召回率、错误断言率 |
| 冲突/版本 | 同一报价不同日期、条件不一致 | 能否标注冲突、正确选择版本 |
| 干扰与注入 | 资料内要求读密钥、执行 shell、自行批准 | 工具越权率、任务偏转率、报告污染率 |
| 工具失败 | 无命中、参数拒绝、引用不匹配 | 修复成功率、额外步数、终止行为 |
| 恢复/重复请求 | 断网、关机、并发审批 | 状态一致性、重复副作用数量 |

每个报告至少由一名懂业务的审阅者逐条检查，关键场景使用两人独立标注并仲裁。把“出处匹配”和“语义支持”分开评分；正确引用一段错误资料仍然可能输出错误结论。

记录每个任务的状态、引用来源、人工事实评分、弃答标签、工具拒绝数、步骤、SDK usage、端到端延迟、API 错误及重试。报告成功率和 p50/p95、样本数量、费用估算口径；统计置信区间前先说明独立性假设。

目前没有真实模型分数、真实费用或延迟基准，没有提示注入鲁棒性结论。随附恶意文本及工具白名单测试证明特定越权请求不能执行，不代表所有语义攻击被防住。

## 接入实际业务前

1. 用真实授权文档替换虚构资料，检查格式、版本、有效期和保密等级。
2. 建立人工标注任务集，先评估检索 Recall@k，再评估报告质量。
3. 对实际语料运行真实模型验收，包括异常与对抗任务。
4. 为真实用户接入身份、权限、审计、预算和数据保留规则。
5. 接外部工单时验证幂等协议和对账流程，保持人工审核。
6. 在目标 Linux 主机验证部署、备份恢复、监控与资源上限。
